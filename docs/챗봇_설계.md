# 계약 비서 챗봇 설계 — 근거 추적형(Grounded Answer)

작성일 2026-07-27 · 분류: **② 축소하여 MVP에 추가** (기존 ③ 연기에서 상향)

---

## 1. 왜 다시 검토했는가

앞선 검토에서 챗봇을 연기 권고한 이유는 두 가지였습니다.

1. 유형 1·2 질문은 결과 화면과 중복된다
2. 자유 질문을 받으면 법률 상담 영역으로 넘어간다

**이 두 가지를 구조로 해결하면 챗봇은 오히려 우리의 최대 차별점이 됩니다.**

핵심 전환: 챗봇을 "답을 만드는 AI"가 아니라 **"질문을 분류해서 검증된 답으로 연결하는 라우터"** 로 설계합니다.

---

## 2. ChatGPT와 무엇이 다른가

사용자가 ChatGPT에 계약서 사진을 올리고 물어봐도 답은 나옵니다. 그럼 우리는 뭐가 다른가?

| | ChatGPT | 페어사인 계약 비서 |
|---|---|---|
| **숫자의 출처** | LLM이 생성 (계산 오류 가능) | **검증 코드 계산 결과만** 사용 |
| **답변의 재현성** | 물어볼 때마다 달라질 수 있음 | 같은 계약서 → **항상 같은 답** |
| **근거 제시** | "일반적으로…" | **계약서 몇 조 + 법령 조문 + 계산식** 3종 동시 표시 |
| **모르는 것** | 그럴듯하게 답함 | **"계약서에서 확인되지 않습니다"로 거절** |
| **답변 이후** | 대화가 끝남 | **행동 버튼** — "이 조항 넣어서 수정본 만들기" → 서명 |
| **범위 밖 질문** | 법률 조언처럼 답변 | **거절 + 고용노동부 1350 안내** |

> **한 문장**: ChatGPT는 답을 만들고, 페어사인은 **검증된 답을 찾아 연결**합니다.

### 거절이 기능이다

가장 강력한 차별점은 역설적으로 **답하지 않는 것**입니다.

"이 상황에서 신고할 수 있나요?"라는 질문에 ChatGPT는 그럴듯하게 답합니다. 우리는 답하지 않고 1350으로 안내합니다. **이게 데모에서 신뢰를 만드는 장면입니다.**

## 3. 구조 — 질문 라우팅

```
사용자 질문
    ↓
[AI] 의도 분류 (Solar) — 정해진 5개 라벨 중 하나로만 분류
    ↓
    ├─ FIELD_LOOKUP    → 추출 JSON에서 값 조회        (LLM 사실 생성 없음)
    ├─ CALCULATION     → 검증 엔진 계산 호출          (LLM 사실 생성 없음)
    ├─ MISSING_CLAUSE  → 표준양식 대비 diff           (LLM 사실 생성 없음)
    ├─ LEGAL_STANDARD  → 법정 기준 상수 테이블 조회    (LLM 사실 생성 없음)
    └─ OUT_OF_SCOPE    → 거절 + 1350 안내            (고정 문구)
    ↓
답변 카드 조립 (값은 위에서 온 것만 사용)
    ↓
[코드] 검증된 KB 스냅샷에서 관련 근거 검색 (로컬 lexical RAG)
    ↓
[AI] 검증 KB·비식별 사실 카드에서 근거·주장 종류·설명 순서 선택 (OpenAI GPT)
    ↓
[코드] strict 스키마 + 사실·KB·출처 관계 검사 후 승인 문구로 조립
    ↓ 통과                              ↓ 실패
GPT 맞춤 설명 표시                 Upstage 안전 폴백
                                      ↓
[AI] 승인된 KB·비식별 사실 카드로 설명 조립 계획 생성 (Solar)
    ↓
[코드] 사실·KB·출처 ID 검증 후 한국어 조립, 실패하면 모델 출력 폐기
    ↓
화면 표시 (근거 3종 + 행동 버튼)
```

### AI가 하는 일 / 하지 않는 일

| AI가 하는 일 | AI가 절대 하지 않는 일 |
|---|---|
| 질문을 5개 라벨 중 하나로 분류 | 숫자 계산 |
| 검증된 근거와 사실 카드에서 설명 계획 선택 | 법적 판단 |
| 승인된 연결·주장 종류와 근거 ID·순서 선택 | 계약 조건·법적 자격 판정 |
| 실패 시 안전한 조립 순서·연결 방식 선택 | 계약서에 없는 내용 추정 |
| — | 라벨 밖의 질문에 답변 |

**숫자와 사실은 100% 코드와 검증된 KB에서 나옵니다.** GPT는 자유 문장을 작성하지
않고 사용할 사실·KB·출처와 설명 순서만 고릅니다. 서버가 관계 검사를 통과한 계획을
승인된 연결 문구와 정확한 원문으로 조립해 결정론적 답변 뒤에 추가합니다.

## 4. 답변 카드 구조

모든 답변은 아래 형식을 따릅니다.

```
┌─────────────────────────────────────────────┐
│ Q. 저 주휴수당 받을 수 있나요?                │
├─────────────────────────────────────────────┤
│ ✅ 시간 요건을 충족합니다                     │
│                                             │
│ 계약상 주 소정근로시간이 18시간이므로          │
│ 주휴수당 지급 요건 중 시간 조건을 충족합니다.  │
│ 다만 실제 지급은 소정근로일 개근 여부에        │
│ 따라 결정됩니다.                             │
├─────────────────────────────────────────────┤
│ 📄 계약서 근거                               │
│    제3조 근로시간 — "주 3일, 1일 6시간"       │
│                                             │
│ ⚖️ 법령 근거                                 │
│    근로기준법 제55조·제18조 (2026년 기준)     │
│                                             │
│ 🧮 계산                                      │
│    3일 × 6시간 = 주 18시간 ≥ 15시간          │
├─────────────────────────────────────────────┤
│ ⚠️ 이 계약서에는 주휴수당 조항이 없습니다      │
│                                             │
│ [ 이 조항을 넣어 수정본 만들기 ]  ← 행동 버튼  │
└─────────────────────────────────────────────┘
```

**필수 구성 요소 4가지**

1. **결론** — 단정 표현 금지, 범위 명시
2. **근거 3종** — 계약서 위치 / 법령 조문+기준일 / 계산식
3. **한계 표시** — 우리가 판정할 수 없는 부분 명시
4. **행동 버튼** — 답변이 실제 조치로 이어지는 지점 (**ChatGPT에 없는 것**)

## 5. 지원 질문 범위 (화이트리스트)

### 답하는 질문

| 라벨 | 예시 질문 | 답변 소스 |
|---|---|---|
| `FIELD_LOOKUP` | 급여일은 언제인가요? / 계약기간이 어떻게 되나요? / 근무 장소는? | 추출 JSON |
| `CALCULATION` | 예상 월급은 얼마인가요? / 최저임금보다 적나요? / 얼마나 손해인가요? | 검증 엔진 |
| `MISSING_CLAUSE` | 빠진 내용이 있나요? / 계약서에 뭐가 더 있어야 하나요? | 표준양식 diff |
| `LEGAL_STANDARD` | 올해 최저임금이 얼마인가요? / 휴게시간 기준이 어떻게 되나요? | 상수 테이블 |

### 답하지 않는 질문 (`OUT_OF_SCOPE`)

- 개별 분쟁의 법적 결론 — "신고할 수 있나요?", "부당해고인가요?"
- 사실관계가 필요한 판단 — "대타를 썼는데 주휴수당 받나요?"
- 계약서에 없는 정보 — "우리 사장님 평판 어때요?"
- 일반 상담 — "알바 그만두고 싶은데 어떡하죠?"

**거절 문구 (고정)**

> 이 질문은 계약서만으로 판단할 수 없습니다.
> 개별 상황에 따라 답이 달라질 수 있어, 고용노동부 고객상담센터(☎1350)에서
> 확인하시는 것을 권합니다. 무료이며 상담 기록이 남습니다.
>
> 대신 제가 답해드릴 수 있는 것: [예상 월급] [빠진 조항] [최저임금 확인]

## 6. 안전장치

### 6-1. GPT 맞춤 설명 계획 검사 (필수 구현)

GPT는 승인된 연결 종류·주장 종류와 사실 ID·KB 문장 ID·출처 ID·설명 순서만 엄격한
JSON 스키마로 반환합니다. 자유 텍스트 필드는 허용하지 않습니다. 코드는 주장 종류와
사실 종류, KB와 출처의 정확한 매핑을 검사합니다. 하나라도 실패하면 계획 전체를 버리고
Upstage 설명 계획, 이어서 결정론적 템플릿으로 폴백합니다. 코드가 만든 최초 결론은 항상
그대로 보존됩니다.

**이 검사는 데모에서 반드시 보여주세요.** "GPT가 질문별 설명 계획은 선택하지만 사용자에게
보이는 사실·법적 문장은 코드와 검증 KB에서만 나오는 구조"라는 점이 핵심 안전 근거입니다.

### 6-2. 컨텍스트 최소화

LLM에 **질문 원문, 계약서 파일·원문, 이름·연락처·생년월일·근무장소를 넘기지
않습니다.** 분류 단계에는 로컬에서 추출한 폐쇄형 특징만, 설명 단계에는 의도·주제·신호
키, 검증 KB 후보와 코드가 만든 비식별 사실 카드만 전달합니다.
OpenAI 요청에는 `store:false`를 지정하며, 외부 제공자의 별도 보관 정책은 별도로
적용될 수 있음을 화면에 안내합니다.

### 6-3. 분류 실패 시

의도 분류가 애매하면 답하지 않고 **되묻습니다**.

> "이 질문이 계약 내용에 관한 것인지 확인하고 싶습니다. 아래 중 가까운 것을 골라주세요."
> [급여 관련] [근무시간 관련] [계약서 누락 항목] [해당 없음]

### 6-4. 상시 노출

채팅 화면 상단 고정:

> 계약서에 적힌 내용과 법정 기준만 알려드립니다. 법률 자문이 아닙니다.

## 7. 데모 설계 — 결정적 장면

### 나란히 비교 (30초)

화면을 반으로 나눠 **같은 질문을 양쪽에 던집니다.**

```
질문: "저 주휴수당 받을 수 있나요?"

┌── ChatGPT ──────────────┐  ┌── 페어사인 ─────────────┐
│ "주 15시간 이상 근무하시  │  │ ✅ 시간 요건 충족        │
│  면 주휴수당을 받으실 수  │  │                         │
│  있습니다. 일반적으로…"   │  │ 📄 계약서 제3조          │
│                          │  │ ⚖️ 근로기준법 제55조     │
│  → 근거 없음             │  │ 🧮 3일×6시간=18시간      │
│  → 개근 요건 누락        │  │ ⚠️ 개근 여부는 별도      │
│  → 내 계약서와 무관      │  │                         │
│                          │  │ [조항 넣어 수정하기] ←   │
└──────────────────────────┘  └─────────────────────────┘
```

### 거절 장면 (20초)

> 질문: "사장님이 급여를 안 주면 신고할 수 있나요?"
>
> 페어사인: "이 질문은 계약서만으로 판단할 수 없습니다. 1350으로 확인하세요."

**멘트**: "저희는 모르는 걸 모른다고 말합니다. 이게 사용자를 지키는 방법입니다."

### 행동 연결 (30초)

답변 카드의 `[조항 넣어 수정하기]` 클릭 → 기존 흐름(수정본 생성 → 서명)으로 자연스럽게 이어짐.

**멘트**: "대화가 계약 수정으로 이어집니다. 이건 범용 AI가 할 수 없습니다."

## 8. 구현 계획

### 개발량 추정

| 작업 | 담당 | 예상 |
|---|---|---|
| 의도 분류 프롬프트 + 5라벨 정의 | A | 2h |
| 라벨별 핸들러 4개 (기존 코드 재사용) | B | 3h |
| 답변 카드 조립 + 근거 3종 매핑 | B | 2h |
| 설명 계획의 사실·KB·출처 ID 검사 | B | 2h |
| 채팅 UI + 답변 카드 컴포넌트 | D | 4h |
| 행동 버튼 → 기존 수정 흐름 연결 | D | 2h |
| 질문 30개 테스트셋 + 정확도 측정 | A | 2h |
| **합계** | | **약 1.5인일** |

**핵심**: 핸들러 4개가 전부 **이미 만든 코드를 호출**할 뿐입니다. 새로 만드는 건 분류기와 UI뿐입니다.

### 일정 배치

| Day | 내용 |
|---|---|
| Day 4 저녁 | 의도 분류 프롬프트 작성, 5라벨 확정 (A) |
| **Day 5** | 핸들러 + 답변 카드 + 후처리 검사 (B), 채팅 UI (D) |
| Day 6 | 테스트셋 30문항 측정, 거절 케이스 점검 |

**전제 조건**: Day 4까지 업로드→검증→수정→서명 흐름이 완성되어 있어야 합니다.
**중단 기준**: Day 5 저녁까지 후처리 검사가 안 붙으면 **챗봇 전체를 뺍니다.** 안전장치 없는 챗봇은 넣지 않는 것보다 나쁩니다.

### 평가 데이터셋 (AI 활용 증빙 제출물)

질문 30개를 라벨별로 준비하고 측정합니다.

- `FIELD_LOOKUP` 8개 — 정답률
- `CALCULATION` 6개 — 숫자 일치율
- `MISSING_CLAUSE` 5개 — 탐지율
- `LEGAL_STANDARD` 5개 — 정답률
- `OUT_OF_SCOPE` 6개 — **거절률** (가장 중요한 지표)

> **거절률이 100%가 아니면 출시 불가**로 기준을 잡으세요. 범위 밖 질문에 한 번이라도 답하면 안 됩니다.

## 10. 남은 위험

| 위험 | 대응 |
|---|---|
