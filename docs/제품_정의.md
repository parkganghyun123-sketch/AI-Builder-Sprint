# 페어사인 — 제품 정의

> 팀 공유용. 발표 자료·화면 문구·README의 기준 문서.
> 작성 2026-07-29. 손글씨 계약서 실측 이후 갱신.

---

## 한 문장

> **법을 몰라서 부당한 계약을 맺는 일이 없도록**
> AI가 계약서를 검사하고, 사장님께 할 말을 찾아주고, 그 계약서를 양측이 갖게 한다.

---

## 문제 — 벽이 세 개다

열여섯 살이 첫 알바 계약서를 받았다. 그 앞에 놓인 것.

| 벽 | 실제 상황 | 근거 |
|---|---|---|
| **모른다** | 최저임금이 얼마인지, 주휴 조건이 뭔지 모른다 | 미작성 이유 1위 "작성해야 하는지 몰라서" 40.4% |
| **말 못 한다** | 알아도 사장님에게 말을 못 꺼낸다 | 대면의 두려움. 여기가 무주공산이다 |
| **증거가 없다** | 계약서를 사장님만 갖고 있다 | 근로기준법 제17조 교부 의무가 지켜지지 않음 |

**"몰라서"가 1위라는 게 핵심이다.** 나쁜 마음이 아니라 무지가 원인이고,
이건 사장님 쪽도 마찬가지다. 그래서 우리는 **고발 도구를 만들지 않는다.**

---

## 해결 — 벽을 차례로 넘는다

```
① 알려준다  ──→  ② 말하게 한다  ──→  ③ 남긴다
   법정 기준 판정      사장님께 보낼 문구      양측이 계약서 보유
```

### ① 알려준다 (`app/validation/`)

최저임금·주휴 시간요건·휴게시간·필수기재를 **코드가** 판정한다.
LLM은 판정에 관여하지 않는다.

> "시급 10,000원 < 2026년 최저임금 10,320원"

**왜 코드인가**

- **재현성** — 같은 조건이면 항상 같은 답
- **설명 가능성** — "왜 위반인가"에 조문과 계산식으로 답한다
- **방어 가능성** — "환각이면요?"에 "판정은 AI가 안 합니다"로 답한다

### ② 말하게 한다 (`app/bridge/`)

**진짜 벽은 탐지가 아니라 대면이다.** 최저임금 미달인 걸 아는 것과,
열여섯 살이 사장님에게 그걸 말하는 것은 전혀 다른 문제다.
그리고 여기를 다루는 서비스가 없다.

> "사장님, 계약서 다시 보다가 시급이 최저임금(10,320원)이랑 차이가 있어서요.
> 혹시 제가 잘못 본 걸까요?"

**고발이 아니라 문의다.** "제가 잘못 본 것일 수도"라는 여지를 남겨
사장님이 방어적으로 나오지 않게 한다.

이 톤은 테스트로 강제한다 — "위반·불법·신고·고발·처벌"이 들어가면 테스트가 깨진다.
숫자는 전부 판정 결과에서 꺼내므로 AI가 지어낼 수 없다(`app/bridge/numbers.py`).

**주제 정통타**: "AI로 인간다움을 표현" = 관계를 지키면서 권리를 찾게 해주는 것.

### ③ 남긴다 (`app/signing/`)

확인된 조건으로 표준계약서를 만들어 전자서명으로 체결한다.

| | 얻는 것 |
|---|---|
| 알바생 | 계약서 원본, 분쟁 시 근거 |
| 사장님 | 교부 의무(제17조)를 이행했다는 증거 |

**한쪽 편을 드는 게 아니라 양쪽 다 안전해진다.**
판정이 종이 한 장으로 끝나지 않고 법적 효력이 있는 문서로 남는다.

---

## 사이에 있는 것 — 사용자 확인

①과 ③ 사이에 **사용자가 값을 확인·수정하는 단계**가 있다.
AI가 읽은 값을 그대로 판정에 쓰지 않는다.

### 이 단계 덕분에 OCR은 급소가 아니다

우리가 하는 건 사진 속 계약서를 **복사**하는 게 아니라,
확인·수정된 조건으로 **표준계약서를 새로 만들어 양측이 다시 합의**하는 것이다.

| OCR 정확도 | 사용자가 하는 일 | 판정 정확도 | 계약서 효력 |
|---|---|---|---|
| 100% | 확인만 | 동일 | 동일 |
| 70% | 세 개 수정 | 동일 | 동일 |
| 0% | 전부 입력 (= 경로 B) | 동일 | 동일 |

### 진짜 위험은 다른 데 있다

못 읽는 건 사용자가 알아챈다. **잘못 읽고 자신 있어 하면 아무도 모른다.**

방어를 두 겹으로 뒀다.

**1) 코드가 AI의 확신을 검사한다** (`app/ai/extract.py`)

시급 0원, 시각 `25:00`, 주 9일 같은 불가능한 값은 AI가 HIGH라고 해도 LOW로 강등.

**2) 낮은 신뢰도 값으로는 "문제 없음"이라고 말하지 않는다** (`app/validation/rules.py`)

LOW인 값으로 판정하면 `UNKNOWN`(확인 필요)을 낸다.
보수적으로 경고하는 방향은 그대로 두되, **불확실한 값으로 안심시키지 않는다.**

## 확인 관문 (`app/review/`)

실측에서 나온 기준이다. `spikes/fixtures/handwritten_01.png`, 손글씨, 3회 반복.

### 무엇이 걸러지고 무엇이 안 걸러지나

| 실패 | AI 신뢰도 | 코드가 잡나 |
|---|---|---|
| 시급 `10 000` → `0000` | HIGH | ✅ 시급 0원은 불가능 |
| 빈칸에 양식 문구 유출 | HIGH | ✅ 라벨 필터 |
| 이름 `박강현` → `박강헌` | HIGH | ❌ **못 잡는다** |

`박강헌`은 실존할 법한 이름이다. `16,000`도 그럴듯한 시급이다.
**코드가 이상하다고 판단할 근거가 없다.**

### 그래서 항상 확인받는 항목

| 항목 | 이유 |
|---|---|
| 임금 금액·임금 형태 | 그럴듯하게 잘못 읽으면 판정이 뒤집힌다 |
| 근로자 성명·대표자·사업체명 | 계약서에 그대로 인쇄된다 |

**5개로 유지한다.** 늘리면 사용자가 대충 다 눌러서 관문이 무력해진다.

### 서명을 막는 세 가지

| code | 뜻 |
|---|---|
| `UNCONFIRMED_FIELDS` | 확인 안 한 항목이 남았다 |
| `NAME_MISMATCH` | 계약서 이름과 입력한 이름이 다르다 |
| (code 없음) | 법정 기준 위반·누락 |

**이름이 다를 때 코드가 고르지 않는다.**
AI가 잘못 읽었을 수도, 사용자가 잘못 입력했을 수도,
종이에 정말 다른 이름이 적혀 있었을 수도 있다. 사용자가 정한다.

## 심사 기준과의 연결

| 심사 항목 | 우리가 대는 것 |
|---|---|
| **인간다움 15점** | ② 말하게 한다 — 관계를 지키면서 권리를 찾게 해준다 |
| **약자 보호 가점 5점** | 만 18세 미만 근로시간 판정(제69조·제70조), 사회초년생이 주 사용자 |
| **완성도·실용성 40점** | 사진 → 판정 → 문구 → 서명 → 양측 보관까지 실제 동작 |
| **AI 활용도 5점** | LLM은 읽기·분류만, 판정은 코드. 근거추적형 구조 |
| **Upstage 가점 +5** | Document Parse + Information Extract를 추출 단계에 사용 |
| **모두싸인 특별상** | 전자서명 + 웹훅 상태 동기화 + 교부 의무 이행 |

### 다른 팀과 겹치는 지점과 갈라지는 지점

"계약서 사진 → AI가 읽고 → 법 위반 판정"은 **거의 모든 팀이 만들 수 있다.**
탐지는 차별점이 안 된다.

우리가 갈라지는 곳은 셋이다.

**② 말하게 한다** — 탐지 다음의 인간적 순간. 여기가 무주공산이다.

**판정을 AI에 맡기지 않는다** — 대부분 "LLM이 판정했어요" 하다가
Q&A의 "환각이면요?"에 무너진다. 우리는 반대로 발표한다.

**양측이 계약서를 갖는다** — 확인에서 끝나지 않고 법적 효력이 있는 문서로 남는다.

## 사용자 흐름

```
사진 업로드
   ↓  Upstage Document Parse + Information Extract (20초)
23개 항목 추출
   ↓  코드가 상식 검사 — 불가능한 값은 신뢰도 강등
확인 화면
   ↓  LOW·NOT_FOUND 강조, 원본 사진 대조, 사용자가 수정
① 법정 기준 판정
   ↓  코드가 계산 (LLM 미사용) — 최저임금·주휴·휴게·필수기재
② 말 꺼내기 문구
   ↓  판정 결과 → 사장님께 보낼 정중한 문의 메시지
서명 요청
   ↓  409 관문 3개 통과 필요
표준계약서 PDF + 모두싸인
   ↓  근로자 → 사업주 순서 서명
③ 양측이 같은 계약서 보유
```

## 심사 예상 질문과 답

**"손글씨 못 읽으면 어떡하나요?"**

> 고치시면 됩니다. 저희가 파는 건 읽기가 아니라 판정입니다.
> AI가 못 읽어도 최저임금 비교와 주휴 계산은 정확하고,
> 그게 사용자가 혼자서는 못 하는 일입니다.

**"AI가 환각을 일으키면요?"**

> 법 판단을 AI에 맡기지 않았습니다. AI는 읽기만, 판정은 코드와 조문으로 합니다.
> 그리고 AI가 자신 있게 틀리는 경우를 실측으로 확인해서,
> 판정에 쓰이는 값은 신뢰도와 무관하게 사용자 확인을 거치게 했습니다.

**"기존 전자계약 서비스와 뭐가 다른가요?"**

> 기존은 **사장님이 시작**합니다. 저희는 **알바생이 시작**합니다.
> 이미 받은 계약서를 검증하고, 문제가 있으면 사장님께 말할 문구까지 만들고,
> 고친 뒤 체결해서 양측이 갖습니다.

**"ChatGPT에 사진 올리면 되지 않나요?"**

> 설명은 해줍니다. 하지만 계약서는 그대로입니다.
> 저희는 수정본을 만들고, 서명까지 하고, 양측이 갖게 합니다.
> 그리고 ChatGPT는 물을 때마다 답이 달라지지만 저희 판정은 항상 같습니다.

**"정확도가 몇 퍼센트인가요?"**

> 합성 이미지는 높게 나옵니다만 그건 깨끗한 인쇄체 기준입니다.
> 실제 손글씨 1장 3회 반복에서 19/23이 안정적으로 정확했고,
> 틀린 항목은 전부 확인 대상으로 표시됐습니다. 표본이 적다는 건 저희도 압니다.

## 팀별 반영 사항

**A (AI)** — 추출 프롬프트에 손글씨 대응 명시.
평가셋에 **실제 촬영 손글씨**를 추가할 것. 합성 이미지 정확도만으로는 방어가 안 된다.
정확도는 3회 반복 기준으로 보고할 것.

**B (검증)** — LOW 값으로 `OK` 판정을 내지 않는다(`_is_unreliable`).
만 18세 미만 근로시간 규칙(제69조·제70조)이 약자 보호 가점의 근거다.

**C (백엔드)** — 확인 관문·이름 불일치 차단·상식 검사·말 꺼내기 문구 완료.
보관함 목록 엔드포인트가 남았다.

**D (프론트)** — 화면이 세 단계를 그대로 보여줘야 한다.

- **확인 화면** — `POST /contracts/review-items` 의 `reasons` 를 그대로 표시.
  신원 항목은 체크박스가 아니라 **입력칸**으로. 값을 채워두고 "맞나요?" 물으면
  사람은 그냥 누른다. 손글씨는 `source_text` 도 AI가 읽은 결과라
  **원본 사진의 해당 위치**를 함께 보여줄 것
- **판정 화면** — 조문과 계산식을 그대로 노출. "왜 위반인가"가 보여야 한다
- **문구 화면** — `POST /contracts/message`. 복사 버튼 필수
- **보관함(`archive`)** — 서사의 마지막 장면. 양측이 갖는다는 걸 눈으로 보여준다

## 하지 말 것

**"모든 계약서를 완벽히 읽습니다"라고 말하지 않는다.**
손글씨 계약서 하나면 무너진다. 한계를 먼저 말하고 그걸 어떻게 다루는지 보여주는 쪽이 강하다.

**손글씨 폰트로 만든 계약서를 "손글씨 테스트"라고 부르지 않는다.**
폰트는 티가 난다. 어려운 케이스를 피해 간 팀으로 보이면 신뢰가 무너진다.

**판정 문구에 LLM이 만든 숫자를 넣지 않는다.**
`app/bridge/numbers.py` 가 대조한다. 근거 없는 숫자가 있으면 템플릿으로 대체한다.

**"고발"·"신고"·"처벌" 이라는 단어를 화면과 발표에서 쓰지 않는다.**
우리는 아무도 나쁜 사람이 되지 않게 하는 도구다.
