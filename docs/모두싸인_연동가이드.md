## 핵심 설계 결정

### 우리는 `POST /documents`를 씁니다 (템플릿 방식 아님)

모두싸인은 서명 요청 방법이 두 가지입니다.

| 방식 | 엔드포인트 | 우리에게 맞는가 |
|---|---|---|
| 템플릿 기반 | `POST /documents/request-with-template` | ❌ 템플릿을 UI에서 미리 만들어야 함. 우리는 계약 조건마다 **PDF를 동적 생성**하므로 부적합 |
| **파일 업로드** | **`POST /documents`** | ✅ 생성한 PDF를 base64로 올려 바로 서명 요청 |

### 🎯 Anchor 기반 필드 배치 — 이게 핵심입니다

서명란 위치를 좌표(x, y)로 계산할 필요가 없습니다. **PDF 안의 텍스트를 기준점으로 지정**하면 모두싸인이 알아서 찾아 배치합니다.

```json
{
  "type": "SIGNATURE",
  "position": {
    "anchor": { "text": "근로자 서명", "offset": { "x": 0.01, "y": 0.005 } }
  },
  "size": { "width": 0.15, "height": 0.05 }
}
```

**왜 중요한가**: 계약 조건에 따라 조항 수가 달라져 서명란 위치가 밀려도, `"근로자 서명"` 텍스트만 있으면 자동으로 따라갑니다. 좌표 계산 코드가 통째로 사라집니다.

**⚠️ PDF 생성 담당(=나)에게 오는 제약**

1. PDF에 **`근로자 서명`, `사업주 서명` 텍스트가 반드시 포함**되어야 함
2. **텍스트 레이어가 있는 PDF**여야 함 (이미지로 렌더링하면 anchor 실패)
3. **폰트 임베딩 필수** — 한글 폰트가 깨지면 anchor를 못 찾음
4. 좌표와 anchor는 **상호 배타적** — 한 필드에 둘 다 넣으면 400 에러

## API 기본 정보

| 항목 | 값 |
|---|---|
| Base URL | `https://api.modusign.co.kr` |
| 인증 | HTTP Basic — `base64(이메일:API_KEY)` |
| 인코딩 | 요청 본문 **UTF-8 필수** |
| API Key 발급 | 설정 → 개인설정 → API KEY (승인 후 메뉴 노출) |
| Webhook 설정 | 설정 → 워크스페이스 관리 → Webhook |

> ⚠️ **API Key는 최초 발급 시에만 전체를 볼 수 있습니다.** 즉시 복사해서 `.env`에 저장하세요.

### 인증 헤더 만들기

```bash
echo -n 'your@email.com:your-api-key' | base64
# → Authorization: Basic <결과값>
```

## 문서 상태 흐름

```
POST 직후          수 초 후            양쪽 서명 완료
    │                 │                     │
    ▼                 ▼                     ▼
ON_PROCESSING ──▶ ON_GOING ──────────▶ COMPLETED
 (처리 중)        (서명 진행 중)         (완료)
```

| 상태 | 의미 |
|---|---|
| `DRAFT` | 작성 중 |
| `ON_PROCESSING` | 문서 처리 중 (POST 응답 직후) |
| `ON_GOING` | 참여자에게 발송됨, 서명 대기 |
| `COMPLETED` | 전원 서명 완료 → `file.downloadUrl`로 최종 문서 |
| `ABORTED` | 중단됨 |
| `PROCESSING_FAILED` | 처리 실패 |

**우리 DB의 `contract.status`를 이 값과 1:1로 맞추면** 상태 동기화 코드가 단순해집니다. (특별상 심사 항목 "연동의 견고성·상태 동기화" 8점)

## 서명 방식 선택

`signingMethod.type` 3가지 중 선택:

| 값 | 설명 | 데모 적합성 |
|---|---|---|
| `EMAIL` | 이메일 발송 | ⭕ 안정적, 기본값으로 |
| `KAKAO` | 카카오 알림톡 | ◎ **데모 임팩트 최고** (폰에 알림 도착) |
| `SECURE_LINK` | 보안 링크 | ⭕ 링크 직접 전달 |

> **데모 전략**: 발표에서 사장님 역할 팀원 폰으로 `KAKAO` 알림이 도착하는 장면이 가장 강력합니다. 단 알림톡은 발송 제약이 있을 수 있으니 **EMAIL을 기본, KAKAO를 데모용**으로 준비하세요.

## Webhook

문서 상태 변경을 실시간 수신합니다. 폴링보다 이쪽이 낫습니다.

- 설정 위치: 모두싸인 **설정 → 워크스페이스 관리 → Webhook**
- 우리 서버에 `POST /webhooks/modusign` 엔드포인트 필요
- **로컬 개발 시**: ngrok 등으로 외부 접근 URL 필요 (Day 1에 미리 준비)

> 폴백: Webhook이 안 되면 `GET /documents/{id}`를 5초 폴링. 데모에는 충분합니다.

## 폴백 설계 (승인 실패 시)

특별상은 포기하되 본상 흐름은 유지합니다.

- `react-signature-canvas`로 서명 캔버스 구현
- 서명 이미지 + 타임스탬프 + 문서 해시(SHA-256) 저장
- 화면에 명시: "**본 서명은 데모용이며 공인 전자서명이 아닙니다**"
- 인터페이스를 동일하게 유지 → 나중에 API가 열리면 갈아끼우기만

```
SignatureProvider (인터페이스)
   ├─ ModusignProvider   (실제)
   └─ CanvasProvider     (폴백)
```

이렇게 추상화해두면 승인이 Day 3에 나도 바로 교체할 수 있습니다.
