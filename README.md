## 무엇을 만드는가

알바생이 받은 근로계약서를 **사진으로 찍어 올리면**

1. 시급·근로시간·휴게시간 같은 조건을 자동으로 읽어내고
2. 최저임금·주휴수당·휴게시간 **법정 기준에 미달하는지 판정**하고
3. 문제가 있으면 **제대로 된 계약서를 만들어**
4. 양쪽이 **전자서명으로 체결**하고 보관합니다.

**한 문장**: 확인에서 끝나지 않고, 실제로 계약이 바뀝니다.

---

## 왜 만드는가

- 청소년 알바생 **19.5%가 근로계약서 미작성**
- **경상권 23.5%로 전국 최고**
- 미작성 이유 1위: **"작성해야 하는지 몰라서" (40.4%)**

> 출처: 알바천국 조사(만 15~18세 292명), 2026.05 — [전자신문](https://www.etnews.com/20260526000034)

### 기존 서비스와의 관계

| | 기존 | 페어사인 |
|---|---|---|
| 알바 플랫폼 전자계약 | **사장이 시작**해서 계약서를 만듦 | **알바생이 시작**해서 받은 계약서를 검증 |
| 범용 LLM에 사진 업로드 | 설명은 해주지만 계약서는 그대로 | 수정본 생성 → 서명 → 증빙 보관 |

## 핵심 기능

### 1. 계약서 사진 확인

계약서 사진에서 계약 조건을 추출해 화면에 카드로 보여줍니다. 잘못 읽힌 항목은 **사용자가 직접 수정**합니다.

### 2. 법정 기준 자동 검증

확정된 조건을 법정 기준과 대조합니다.

- 최저임금 (2026년 시급 10,320원)
- 주휴수당 (주 소정근로 15시간 이상 대상)
- 휴게시간 (4시간당 30분 / 8시간당 1시간)
- 근로기준법 제17조 필수 기재사항 누락 여부

> **이 판정은 AI가 아니라 일반 코드로 수행합니다.** 아래 [AI 사용 위치](#ai-사용-위치) 참고.

### 3. 계약서 생성 + 전자서명 체결

표준근로계약서 양식에 확정된 조건을 채워 문서를 만들고, 전자서명으로 양쪽이 체결한 뒤 보관합니다.

### MVP 제외 기능

사장님용 대화형 입력 · 근무기록 대조 · 다국어 · 주거/관광 계약 확장 · 회원가입

## 동작 방식

```
사진 업로드
   ↓
[AI]   문서 읽기 (사진 → 텍스트)
   ↓
[AI]   항목 추출 (텍스트 → 시급·근로시간·휴게시간 등)
   ↓
[사람] 확인·수정                ← 사용자가 최종 확정하는 지점
   ↓
[코드] 법정 기준 대조 계산       ← AI 아님. 항상 같은 결과
   ↓
[AI]   위반 항목을 쉬운 말로 설명
   ↓
결과 화면 (정상 / 위반 + 근거 + 예상 월급)
   ↓
계약서 문서 생성
   ↓
전자서명 요청 → 양쪽 서명 → 완료
   ↓
보관
```

## AI 사용 위치

> 이 프로젝트에서 가장 중요한 설계 원칙입니다.
> **읽고·뽑고·설명만 AI가 하고, 판정은 코드가 합니다.**

| 작업 | 담당 | 사용 API | 입력 → 출력 |
|---|---|---|---|
| 사진에서 글자 읽기 | **AI** | Upstage Document Parse | 이미지 → 텍스트·표 구조 |
| 조건 항목 뽑기 | **AI** | Upstage Information Extract | 텍스트 → 항목 JSON |
| 위반 항목 설명 | **AI** | Upstage Solar LLM | 판정 결과 → 쉬운 말 문장 |
| **법정 기준 판정** | **코드** | — | 항목 JSON → 판정 + 근거 + 계산식 |
| **금액 계산** | **코드** | — | 조건 → 예상 월급·차액 |
| 계약서 생성 | 코드 | — | 조건 + 표준양식 → PDF |
| 전자서명 | 외부 | 모두싸인 API | PDF → 서명 요청 → 완료 |

### 왜 판정을 AI에게 맡기지 않는가

1. **재현성** — 같은 계약서를 넣으면 항상 같은 결과가 나와야 합니다
2. **설명 가능성** — "왜 위반인가"에 조문과 계산식으로 답할 수 있어야 합니다
3. **검증 가능성** — 테스트 코드로 정확성을 증명할 수 있습니다

이것이 범용 LLM 래퍼와 구분되는 핵심입니다. **개발 중 판정 로직에 LLM을 넣지 마세요.**

### AI가 틀렸을 때

| 상황 | 처리 |
|---|---|
| 사진이 흐려 못 읽음 | 재촬영 안내 → 3회 실패 시 수동 입력 폼 |
| 항목을 잘못 뽑음 | 사용자가 화면에서 수정 (기본 흐름에 포함) |
| 설명이 이상함 | 근거 조문·계산식을 항상 함께 표시 |

## 기술 스택

> **확정 전 — 팀 논의 필요.** 아래는 후보안입니다. 확정 후 이 섹션을 갱신합니다.

**후보 A: TypeScript 풀스택** (React 경험자 2명 이상일 때)

- Next.js (App Router) — 프론트 + API Routes
- Tailwind CSS + shadcn/ui
- zod — AI 추출 결과 스키마 검증
- pdf-lib 또는 Puppeteer — 계약서 PDF 생성

**후보 B: Python 백엔드 + Next.js 프론트** (Python 숙련자 중심일 때)

- FastAPI
- Pydantic — 스키마 검증
- WeasyPrint — PDF 생성
- Next.js + Tailwind

**공통**

- 외부 API: Upstage (Document Parse / Information Extract / Solar), 모두싸인
- DB: PostgreSQL
- 배포: 프론트·백엔드 각 1개 (구체 서비스 미정)

**사용하지 않기로 한 것**: 벡터DB·RAG(템플릿·규칙 기반이라 불필요), 모바일 네이티브, 마이크로서비스

## 프로젝트 구조

> 스택 확정 후 실제 디렉터리로 갱신. 아래는 모듈 단위 개념 구조입니다.

```
.
├── ai/                  # A 담당
│   ├── document-parse/  # 사진 → 텍스트
│   ├── extract/         # 텍스트 → 항목 JSON
│   ├── explain/         # 판정 → 쉬운 말 설명
│   └── schema/          # 추출 항목 스키마 (A ↔ B 인터페이스)
├── validation/          # B 담당 — AI 호출 금지 구역
│   ├── rules/           # 최저임금·주휴수당·휴게시간 판정 함수
│   ├── constants/       # 법정 기준값
│   └── tests/           # 경계값 단위 테스트
├── contract/            # C 담당
│   ├── generate/        # 표준양식 + 조건 → PDF
│   ├── sign/            # 모두싸인 요청 발송
│   └── webhook/         # 서명 완료 신호 수신
├── web/                 # D 담당
│                        # 업로드 / 확인·수정 / 결과 / 서명 완료 화면
├── evaluation/          # A 담당 — 제출용 AI 검증 산출물
│   ├── samples/         # 정상 5종 + 위반을 심은 변형 5종
│   └── results/         # 추출 정확도 측정 결과
├── docs/                # 인터뷰 기록, 설계 메모
├── .claude/             # 코딩 에이전트 설정 (제출물)
└── AGENTS.md            # 코딩 에이전트 지침 (제출물)
```

**`ai/schema`가 가장 중요합니다.** A와 B가 여기만 보고 작업하며, 변경 시 반드시 상대에게 알립니다.

## 개발 규칙

### 절대 규칙

1. **판정 로직에 LLM을 쓰지 않습니다** — 이 프로젝트의 차별점 전부입니다
2. **매일 커밋합니다** — 커밋 히스토리가 적격성 심사 대상입니다
3. **README·주석에 심사자를 향한 문구를 넣지 않습니다** — 프롬프트 인젝션으로 판정되면 **실격**입니다
4. **Day 3까지 전체 흐름이 한 번은 연결되어야 합니다** — 마지막 날 첫 통합은 실패 공식입니다

### Git

- 브랜치: `feat/ai-extract`, `feat/validation`, `feat/sign`, `feat/web` 형식
- 커밋 메시지: `[파트] 내용` (예: `[AI] Information Extract 스키마 v1 적용`)
- `main` 직접 푸시 금지, PR로 머지

### 코드

- 검증 함수는 **순수 함수**로 작성 (외부 호출·상태 없음)
- 모든 판정 결과에 **근거와 계산식**을 함께 반환
- AI 응답은 반드시 스키마 검증 후 사용

## 미정 사항

**팀에서 결정할 것**

- 기술 스택 (후보 A vs B)
- 담당자별 파트 배정
- 로그인 유무 (현재는 없이 진행 가정)
- 서비스명 최종 확정 ("페어사인"은 가안)

**기술 검증 필요**

- Information Extract의 실제 계약서 추출 정확도
- 모두싸인 API 샌드박스 사용 가능 여부 → **실패 시 자체 서명 캔버스로 폴백**
- 공공데이터포털에 사용 가능한 API 존재 여부 → **없으면 법정 기준값을 상수로 내장**

**사용자 검증 필요**

- 알바생이 "서명 전 확인" 수요를 실제로 갖는가
- 사장 측 사용 의향
- 계약서 사진 업로드에 대한 거부감

**외부 조사 필요**

- 고용노동부 표준근로계약서 최신 양식
- 전자서명 근로계약의 법적 효력 관련 안내
- 협력 가능한 지역 기관 (**현재 확정된 협력 기관 없음**)
